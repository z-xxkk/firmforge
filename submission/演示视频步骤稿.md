- 准备两段已有记录用来展示"没通过时"：左侧历史里 11 月 16 日下午那条"每 2 秒读一次芯片温度和 ADC…"（ADC 模块 4 次没通过的那次）。

## 第 1 段　开场：平台是什么（约 20 秒）

**画面**：软件首页（对话页），左边导航依次点一下 对话、知识库、工作流、团队、设置，再回到对话。

**旁白**：固件工坊是一个面向嵌入式固件开发的多 Agent 编排与验证平台。用户用一句话描述要在开发板上实现的功能，平台拆成模块，调度多个大模型 Agent 分工写代码和测试，用编译器、上板测试、接线实测这些客观判定器检查，没通过就诊断、交给对应的 Agent 修，最后交付在真实开发板上验证过的工程。

## 第 2 段　Agent 团队与工作流编排（约 40 秒）

**画面**：
1. 点"团队"：列表里的 analyst、researcher、designer、coder-fast、coder-strong、tester、diagnoser……点一个 coder-fast，右边显示档位、工具、历史表现。
2. 点"工作流"：顶上选 `firmware_review`，画布上看到 规则 → 设计 → 接线/每个模块各跑（编码、写测试并行 → 检查 → 修正循环 → 审查）→ 集成。点一个步骤，右边属性栏显示内容；下面代码区和画布同步。
3. 点"开始检查"：下面列出空跑 6 种情况，点其中一种，画布上依次点亮经过的步骤。

**旁白**：每个 Agent 有自己的角色、模型档位、工具和记忆，有版本管理，调度器按历史成绩挑人。工作流用可视化设计器编排，支持并行、条件、循环、子流程和人工确认节点，保存成 TOML 文件由解释器执行；检查时用真正的解释器空跑几种情况，保证图上画的就是实际执行的。

## 第 3 段　发需求、确认设计（约 30 秒）

**画面**：
1. 回到对话，点"新对话"，确认 流程=上板、规则=规则库、模型=快档、"设计后等我确认"打开。
2. 发需求："每 2 秒读一次芯片温度和 ADC 引脚上的电压，记录开机以来的最高温度，并把最高温度存进 NVS；掉电重启后先读出并打印上次保存的最高温度。"
3. 等设计出来：对话里列出 4 个模块和接线（GPIO0 → 3V3，写明先拔掉原来的跳线）。右边工程图出现模块。点"确认，开始写"。

**旁白**：平台先只针对需求里提到的外设查规则，这次温度、ADC、NVS 的规则库里都有，直接复用。设计 Agent 把需求拆成硬件层和逻辑层，写好接口、验收条件，还要给出完整接线——每根线另一端接什么、为什么、接好后应该测到什么。板上能读电压的引脚都被占了，它写明了要先拔掉一根旧跳线。

## 第 4 段　接线与自检（约 40 秒，演示"验证"最直观的一段）

**画面**：
1. 出现接线清单卡片。**故意先不接线**，直接点"已接好，开始自检"。
2. 平台烧录自检程序，出现"自检没对上：ADC GPIO0：几百 mV（应在 2800–3100 mV）"。
3. 拔 USB → 拔掉 GPIO0–GPIO1 跳线 → GPIO0 接 3V3 → 插回 USB → 点"已接好，开始自检"。
4. 显示"对上了（3005 mV）"，开始写代码。

**旁白**：写代码之前先接线。平台不相信任何人或 Agent 说的"接好了"，而是烧一个自己写的小程序去实测：线没接好就拦下来，告诉你实测到多少。之前没有这一步时，Agent 对着一根没接好的线白试了 4 次。每根线的实测状态会写进后面所有 Agent 的提示词里。

## 第 5 段　调度执行与修正循环（约 50 秒）

**画面**（这段可以快进）：
1. 右侧工程图里模块依次变成运行中、通过；点"调度"标签，看为什么这个模块交给 coder-fast（成功率、成本、负载的得分）。
2. 点 nvs_store 模块，下面"过程"标签显示修正时间线：第 1 次上板没过 → 诊断：错在测试，要删掉某个用例 → 平台核对"已经删掉" → 第 2 次通过 → 平台故意改坏代码检验测试 → 补测试……
3. 对话里出现"平台把代码故意改坏 3 处，测试发现了……"。

**旁白**：编码和写测试由不同的 Agent 同时进行，测试 Agent 看不到实现。每个模块合规、编译、烧到板子上跑测试；没通过就由诊断 Agent 判断错在代码、测试、规则、设计还是硬件，交给对应的 Agent 修，平台还会核对交代的事有没有照办。通过以后，平台故意把代码改坏几处，看测试能不能发现，发现不了就让测试 Agent 补，防止测试写得太松。

## 第 6 段　集成与交付（约 30 秒）

**画面**：
1. 对话里"主程序第 N 次：上板跑了两轮，期望的输出都看到了"。
2. 点"上板"标签或打开运行目录里的串口记录：第一轮"无历史记录"、每 2 秒一行温度和电压；第二轮"上次保存的最高温度 xx °C"。
3. 对话里"完整工程已交付：…/firmware"，打开这个文件夹给评委看一眼（源码、验证报告）。

**旁白**：所有模块通过后，平台写主程序把模块串起来，编译整个工程烧到板子上，擦掉 NVS 后复位跑两轮：第一轮验证首次上电的行为，第二轮验证掉电保存。最后交付一个可以直接烧录的完整工程和验证报告。

## 第 7 段　没通过时怎么办（约 30 秒）

**画面**：左侧历史点开 11 月 16 日下午那条（ADC 4 次没通过），说明那次是旧版本；然后展示新版本"没通过"卡片（截图 `submission/screenshots/06_没通过的讲解与人工放行.png`，或者剪辑时插入这张图）：经过、风险、三个按钮。

**旁白**：模块用完次数还没通过时，平台按运行记录讲清楚从第一次失败到现在发生了什么——比如这次代码 4 次都没改过，问题全在测试和验收条件上——再列出放行的风险，让人选择接着修、人工放行或者放弃。人工放行要写理由、再确认一次，结论如实记"人工放行"，不算通过。

## 第 8 段　量化结果与收尾（约 20 秒）

**画面**：方案书第 7 章的表格（或 PPT 对应页）。

**旁白**：在 6 道上板测试题上，完整系统的通过率从 39% 提升到 67%，提升超过两倍标准误；单 Agent 基线是 33%。4 道平台没见过的留出题全部通过。这个演示从一句话需求到上板交付，用快档模型花了不到一块钱、二十分钟左右。代码和全部运行记录都在 GitHub 上，可以复现。
