## 二、环境要求

- 操作系统：Linux（开发和测试都在 Ubuntu 24.04 上）。
- Python 3.11 或更高。核心库只用标准库；桌面软件需要 PySide6。
- 大模型：DeepSeek（OpenAI 兼容接口），需要自己的 API 密钥。
- 上板验证（可选）：ESP32-C3 开发板（ESP32-C3 SuperMini）和 ESP-IDF v6.1。没有开发板时，硬件层只做到编译和合规检查，会明确标为“跳过”，不会判为通过。

## 三、安装

```bash
git clone https://github.com/z-xxkk/firmforge.git
cd firmforge
python3 -m venv .venv
.venv/bin/pip install -e ".[gui,sources]"
cp .env.example .env      # 打开 .env，填写 DEEPSEEK_API_KEY
```

## 四、使用

```bash
.venv/bin/firmforge doctor      # 检查工具链、开发板、ESP-IDF 是否可用
.venv/bin/firmforge gui         # 打开桌面软件
```

桌面软件里：

1. 左侧点“对话” → “新对话”，流程选“上板”，规则选“规则库”，模型选“快档”。
2. 在输入框用一句话写需求，例如“每 2 秒读一次 MPU6050 的三轴加速度和芯片内部温度，记录最大加速度合值并保存到 NVS，断电重启后先打印上次的最大值”，发送。
3. 设计好后确认；按接线清单接好线后点“已接好，开始自检”。平台实测对上后自动写代码、测试、上板、修正，最后交付完整工程，可以“导出代码”。
4. 其他页面：知识库（规则和出处）、工作流（图形化编排与预演）、团队（AI 角色与历史成绩）、设置（模型、工具、MCP）。

## 五、没有开发板也能复现的内容

```bash
.venv/bin/python -m unittest discover -s tests          # 632 个单元测试（假模型，不联网、不花钱）
.venv/bin/firmforge bench --out results/bench           # 性能测试（假模型）
.venv/bin/firmforge agents                              # 列出 AI 角色：版本、档位、工具、历史表现
.venv/bin/firmforge mcp --selftest                      # MCP 服务自检
```

完整的设计文档见仓库的 `docs/ARCHITECTURE.md`，全部设计决定见 `docs/DECISIONS.md`，测量方案与结果见 `docs/TEST_PLAN.md`。
