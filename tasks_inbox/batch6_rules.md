## 题 17：定点数 PID 控制器 pid_ctrl（状态机，难度 3）

### 参照了什么

| 内容 | 原文要点 | 出处 |
|---|---|---|
| 抗饱和（积分限幅） | 告诉 PID 输出范围；积分项超出范围时钳在边界，"停止累加" | [1] Reset Windup |
| 输出限幅 | P 和 D 还会让输出越界，所以输出也要钳在范围内；两个都要钳，只钳输出的话积分会继续涨 | [1] Reset Windup |
| 微分冲击 | 设定值突变会让"误差的微分"变成一个尖峰；改为对**测量值**求微分（减去 Kd × 测量值变化） | [1] Derivative Kick |
| 调参不突变 | 把 Ki 放进积分里：每次累加 Ki × 误差，而不是先累加误差再乘 Ki；改 Ki 时输出不会跳 | [1] Tuning Changes |
| 修改限幅 | 立即把当前输出和积分项钳到新范围 | [1] Reset Windup 的 SetOutputLimits |
| 手动 → 自动无扰切换 | 切换时积分项 = 当前输出（再钳到范围内），上一次测量值 = 当前测量值 | [1] Initialization |
| 手动模式 | 计算函数直接返回，不更新任何状态 | [1] Initialization |

### 怎么用

★ **用整数定点数，不用浮点**：增益 Kp、Ki、Kd 以 1/1024 为单位（例如 Kp = 1.5 写成 1536）；积分项内部也放大 1024 倍保存，保留小数精度；中间结果用 64 位整数，防止溢出。理由：Cortex-M3 没有浮点单元，前面几道题也都要求整数运算。

★ **采样周期由调用方负责**：每个采样周期调用一次计算函数；增益是"每次采样"的增益（Beauregard 的代码把采样时间换算进 Ki、Kd，这里交给调用方先换算好）。理由：题目没有时钟，和前面几道题一致。

### 规则

| 情况 | 应该怎样 | 依据 |
|---|---|---|
| 初始化 | 设定增益和输出范围；★ 初始为**手动模式**，输出 0，积分 0 | [1]（原代码 inAuto 初值为 false） |
| ★ 增益为负，或输出下限不小于上限 | 初始化 / 设置失败，什么都不改 | Beauregard 的代码里下限大于上限时直接返回；这里把相等也算不合法 |
| 每次计算（自动模式） | 误差 = 设定值 − 测量值；积分 += Ki × 误差，然后钳到 [下限×1024, 上限×1024]；输出 = (Kp × 误差 + 积分 − Kd × (测量值 − 上次测量值)) ÷ 1024；再钳到 [下限, 上限]；记下本次测量值 | [1] |
| ★ 除以 1024 的取整 | 按 C 语言整数除法，**向零取整**（不用右移，右移对负数是向下取整） | 与 MPU6050、DS18B20 题一致 |
| 手动模式下计算 | 返回当前输出，不改积分，也不记测量值 | [1] |
| ★ 手动模式设定输出 | 可以，钳到范围内；自动模式下设定输出无效 | [1] 的推论（手动时由用户直接给输出） |
| 切换到自动（从手动） | 积分 = 当前输出 × 1024（钳到范围内），上次测量值 = 调用时给的当前测量值 | [1] Initialization |
| ★ 已经是自动又切换到自动 | 什么都不做（不重新初始化） | 原文评论区指出的问题，作者认同 |
| 修改增益 | 只改增益，积分保持不变（所以输出不突变） | [1] Tuning Changes |
| 修改输出范围 | 立即把当前输出和积分项钳到新范围 | [1] |
| 参数为 NULL | 设置函数返回失败；计算函数返回 0 | 与前几道题一致 |

**判卷方式**：隐藏测试用另一种写法独立算出期望输出，逐步对照：阶跃响应、设定值突变时输出不出现尖峰、长时间饱和后设定值回落时立即响应（不拖延）、运行中改 Ki 时输出不跳、手动切自动时输出不跳、负数误差的取整、64 位中间结果不溢出。

**错卷（计划）**：对误差求微分（设定值突变时出现冲击）；积分不限幅（饱和后回落拖延）；Ki 放在积分外面（改 Ki 时输出跳）；切换到自动时积分清零（输出跳到 0）。

## 题 18：步进电机梯形加减速 stepper_ramp（状态机，难度 3）

### 参照了什么

Atmel《AVR446: Linear speed control of stepper motor》[2]，基于 D. Austin《Generate stepper-motor speed profiles in real time》（2005）。

| 内容 | 原文要点 | 出处 |
|---|---|---|
| 参数 | 走多少步、加速度、减速度、最高速度；加减速度单位 0.01 rad/s²，速度单位 0.01 rad/s；步数 −64000…64000，加减速度 71–32000，速度至少 12 | [2] 3.1 节菜单说明 |
| 最短间隔（最高速度） | min_delay = A_T_x100 ÷ speed，其中 A_T_x100 = α × 计时器频率 × 100（α = 2π / 每圈步数） | [2] 3.2.1 |
| 整数写法 | max_s_lim 的公式写成 speed² ÷ (A_x20000 × accel ÷ 100)，A_x20000 = α × 20000；与原文公式等价（我推导的整数形式） | [2] 3.2.1.1 |
| 第一步的间隔 | c0 = T1_FREQ_148 × √(A_SQ ÷ accel) ÷ 100，其中 T1_FREQ_148 = 0.676 × 计时器频率 ÷ 100，A_SQ = 2α × 10¹⁰；乘 0.676 是为了补偿近似公式在第一步的误差 | [2] 2.3.1、3.2.1 |
| 加速到最高速度要几步 | max_s_lim = speed² ÷ (2α × accel × 100) | [2] 3.2.1.1 |
| 不考虑最高速度时何时开始减速 | accel_lim = step × decel ÷ (accel + decel) | [2] 3.2.1.1 |
| 两种情形 | max_s_lim < accel_lim：先到最高速度（梯形）；否则还没到最高速度就要减速（三角形） | [2] 3.2.1.1、3.2.1.2 |
| 减速段的步数 | 梯形：decel_val = −max_s_lim × accel ÷ decel；三角形：decel_val = −(step − accel_lim) | [2] |
| 每一步的新间隔 | new = d − (2d + rest) ÷ (4 × accel_count + 1)；rest = (2d + rest) 除以 (4 × accel_count + 1) 的余数（保留余数提高精度） | [2] 3.2.2.1 |
| 状态机 | STOP → ACCEL（走 1 步时直接 DECEL）；ACCEL 到最高速度 → RUN；到开始减速的那一步 → DECEL；DECEL 的 accel_count 从 decel_val（负数）加到 0 → STOP | [2] 3.2.2 |
| 计数 | step_count 从 0 开始每步加 1；decel_start = step + decel_val | [2] 3.2.2.1 |

### 怎么用

★ **固定常数**：计时器频率 1 MHz、每圈 200 步（1.8° 步进电机最常见的规格）。头文件直接给出算好的整数常数：A_T_x100 = 3141592、T1_FREQ_148 = 6760、A_SQ = 628318530、A_x20000 = 628（都按原文公式算出后截掉小数）。理由：不让 Agent 碰浮点。

★ **事件驱动**：开始一次移动后，调用方每次取"下一步"：模块告诉调用方"现在走一步，然后等多少个计时器周期再取下一步"，直到移动结束。这正是原文定时器中断里做的事。

★ **平方根用整数平方根（向下取整）**：原文用 sqrt 函数（浮点）；本题不能用浮点，要自己实现整数平方根。

### 规则

| 情况 | 应该怎样 | 依据 |
|---|---|---|
| 开始移动 | 按上表的公式算出 min_delay、c0、max_s_lim、accel_lim、decel_val、decel_start | [2] |
| ★ max_s_lim 或 accel_lim 算出 0 | 当作 1 | 我的选择：避免出现 0 步的加速段（附带的源码没下载到，无法核对原作者的做法） |
| ★ decel_val 算出 0 | 当作 −1（至少减速 1 步） | 同上 |
| c0 ≤ min_delay | 第一步就用 min_delay，直接进入 RUN | [2] |
| ★ 直接进入 RUN 时 | "上一次加速的间隔"记为 min_delay（原文没有给这种情况赋值） | 我的选择：避免用到未初始化的值 |
| ★ 只走 1 步 | 直接进入 DECEL，accel_count = −1，间隔用 c0（原文这里写死了 1000） | 我的选择：1000 只适合原文的计时器频率 |
| ACCEL 每一步 | 按上表公式算新间隔；走到 decel_start 那一步转 DECEL（accel_count = decel_val）；否则新间隔 ≤ min_delay 时，记下"上一次加速的间隔"，间隔改为 min_delay，余数清零，转 RUN | [2] |
| RUN 每一步 | 间隔保持 min_delay；走到 decel_start 那一步转 DECEL，间隔改为"上一次加速的间隔" | [2] |
| DECEL 每一步 | 按同一公式算新间隔（这时分母为负数，间隔变长）；accel_count 加到 0 时转 STOP | [2] |
| ★ 整数除法和余数 | 一律按 C 语言规则（向零取整，余数与被除数同号），中间结果用 64 位 | 我的选择：分母为负时 C 的规则与数学上的取整不同，必须写明 |
| ★ 方向与位置 | 步数为负表示反转；每走一步位置计数加 1 或减 1 | [2] 的步进计数器 |
| ★ 参数超出范围（步数 0 或超过 ±64000、加减速度不在 71–32000、速度不在 12–32000） | 拒绝，不开始移动 | 原文菜单给的范围；速度上限是我定的，防止平方溢出 |
| ★ 移动还没结束又要开始新的移动 | 拒绝 | 原文"电机运行时新命令被阻止" |

**判卷方式**：隐藏测试里的期望间隔序列，是我用 Python 按同样的公式另写一遍算出来的（Python 和 C 的整数除法规则不同，生成时专门按 C 的规则处理），不是拿参考答案跑出来的。测试覆盖：梯形和三角形两种曲线、只走 1 步、第一步就达到最高速度、反转、步数上限、各参数边界、移动中拒绝新命令；另外检查总步数正确、加速段间隔单调减小、减速段单调增大。

**错卷（计划）**：不保留余数；梯形和三角形判断写反；减速段步数算错一步；第一步不乘 0.676 补偿。

## 题 19：固定块内存池 mem_pool（数据结构，难度 3）

### 参照了什么

| 内容 | 原文要点 | 出处 |
|---|---|---|
| 用途 | 嵌入式系统里代替 malloc：一块缓冲区切成大小相同的块，分配和释放都是常数时间 | [3] |
| 块大小 | 至少能放下一个指针，并且是对齐单位的整数倍；缓冲区按同样的单位对齐 | [3] 文档；[4] create_free_list 检查"block_size 和 buffer 都要按 sizeof(void *) 对齐" |
| 空闲链表 | 空闲块的头几个字节存"下一个空闲块"的指针，不额外占内存 | [3] |
| 分配顺序 | 初始化时从最后一块往前串，所以第一次分配拿到最前面的块；释放的块下一次最先被分配（后进先出） | [4] create_free_list、k_mem_slab_free |
| 释放时检查指针 | 指针必须在缓冲区内，并且正好落在某一块的起点，否则报错 | [4] slab_ptr_is_good |
| 统计 | 已用块数、空闲块数、历史最大已用块数 | [3] |
| 重复释放 | 同一块内存只能释放一次，重复释放会破坏空闲链表 | [5] MEM31-C、[6] CWE-415 |

### 规则

| 情况 | 应该怎样 | 依据 |
|---|---|---|
| ★ 对齐单位 | `sizeof(void *)`（STM32 上是 4 字节，电脑上是 8 字节，代码不能写死） | [4] |
| 初始化：块大小不是对齐单位的整数倍、小于一个指针，或缓冲区没对齐 | 失败 | [4] |
| 初始化：块数 = 缓冲区大小 ÷ 块大小（余下的边角不用）；块数为 0 | 失败 | [3] |
| ★ 块数上限 | 头文件给出（例如 256），超过则失败 | 我的选择：用于下面的"重复释放"检查 |
| 分配 | 有空闲块就返回一块，没有返回 NULL；顺序如上表（先按地址从小到大，之后后进先出） | [4] |
| 释放：指针不在缓冲区内 | 报"不是本池的内存"，什么都不改 | [4] |
| 释放：在缓冲区内但不在块的起点 | 报"指针没对准块的起点"，什么都不改 | [4] |
| ★ 释放：这一块本来就是空闲的 | 报"重复释放"，什么都不改 | [5]、[6]；Zephyr 本身不查，这里用一个"哪些块正在使用"的位图来查 |
| ★ 释放 NULL | 什么都不做，返回成功 | 与 C 标准库 free(NULL) 一致 |
| 统计 | 已用、空闲、历史最大已用；★ 提供"全部释放"（重置）时历史最大值保留 | 我的选择 |
| ★ 分配出的块内容 | 不清零（与 malloc 相同） | 我的选择 |

**判卷方式**：隐藏测试检查分配顺序、用完返回 NULL、各种错误释放（不同池的指针、中间位置、末尾之后一点点、重复释放、释放 NULL）都不破坏池；随机分配释放上万次后，统计数字与测试自己维护的账一致、分出去的块互不重叠、都在缓冲区内且对齐。

**错卷（计划）**：不查重复释放；不查指针是否对齐到块起点；范围检查差一（把紧挨着缓冲区末尾的地址当成池内）；历史最大值不更新。

## 题 20：Flash 键值存储 flash_kv（数据结构，难度 3，多模块）

### 参照了什么

Zephyr NVS 官方文档 [7] 与源码 [8]：

| 原则 | 原文要点 | 出处 |
|---|---|---|
| 追加写 | 数据一条接一条往后写（Flash 只能把 1 变成 0，不能原地改写） | [7] |
| 最新的有效 | 同一个 id 写多次，以最后一条为准；读的时候从新到旧找 | [7]、[8] nvs_prev_ate |
| 先写数据、后写元数据 | 写到一半断电的条目没有有效的元数据，启动时被忽略 | [7] |
| 元数据带校验 | 元数据有 CRC，"只用来确认写入完整" | [7]、[8] crc8 |
| 删除 | 写一条长度为 0 的条目 | [8] nvs_flash_wrt_entry |
| 没变就不写 | id 和数据都没变时不写 Flash（减少擦写） | [7] |
| 整理（垃圾回收） | 扇区写满后，把仍然有效的条目复制到空扇区，再擦掉旧扇区；总要留一个空扇区用来复制 | [7]、[8] nvs_gc |
| 断电恢复 | 启动时检查，忽略缺失或校验不对的条目 | [7] |

### 简化版的设计（★ 全部是我定的）

| 项目 | 规则 | 为什么 |
|---|---|---|
| ★ 扇区 | 只用 2 个扇区，每个 1024 字节：一个在用，一个备用 | NVS 至少 2 个扇区；2 个最简单，又能演示整理和断电恢复 |
| ★ 扇区头 | 扇区开头 4 字节：标记 `KV`（2 字节）+ 序号（2 字节）；整理时**最后**才写新扇区的头 | 断电时，没写头的扇区不会被当成有效 |
| ★ 条目格式 | 6 字节头（id 2 字节、长度 2 字节、CRC-16 2 字节，低字节在前）+ 数据；整条补齐到 4 字节的倍数（补 FFh） | CRC 同时覆盖头和数据，写到一半一定校验不过 |
| ★ CRC | CRC-16/CCITT-FALSE（多项式 1021h，初值 FFFFh），覆盖 id、长度和数据 | 常用、知识库里有参数表 |
| ★ id 范围 | 0–FFFEh（FFFFh 是"擦除后的空白"） | NVS 也把 FFFFh 留作特殊值 |
| ★ 数据长度 | 1–64 字节；长度 0 表示删除 | |
| ★ 写入 | 新值与当前值完全相同就不写；放不下就先整理再写；整理后仍放不下报"空间不够"，原数据保持不变 | [7] 的原则 |
| ★ 整理的步骤 | 擦除备用扇区 → 把每个 id 的最新有效值（已删除的跳过，正在写的这个 id 也跳过）依次复制过去 → 写入新值 → 最后写扇区头（序号 + 1）→ 擦除旧扇区 | 先复制、最后写头，任何一步断电都能恢复 |
| ★ 启动（挂载） | 两个扇区都没有有效头：全部擦除，扇区 0 写序号 0 的头；只有一个有效：用它；两个都有效：用序号"更新"的那个（按 16 位回绕比较），擦掉另一个 | 对应整理过程中各个断电时刻 |
| ★ 启动时扫描 | 从扇区头之后逐条检查：遇到全 FFh 的头就是结尾；遇到校验不过或长度不合理的条目，后面的空间不再使用（下一次写入会触发整理） | Flash 上写过一半的位置不能再写 |
| ★ 删除 | 不存在的 id 删除时什么都不做，返回成功 | |
| ★ 读取 | 返回最新值；不存在或已删除报"没有"；缓冲区太小报"缓冲区不够"，并告诉调用方实际长度 | |

### 怎么用

题目提供 Flash 接口头文件（锁定）：读、写（只能把 1 变成 0）、擦除一个扇区。驱动提供：挂载、写、读、删除、查询剩余空间。很适合拆成"CRC / 扇区与条目格式 / 整理 / 对外接口"几个模块。

**判卷方式**：隐藏测试带一块"假 Flash"：写入时只能把 1 变成 0（违反就记一次错误）、记录擦除次数、可以设定"写到第 N 个字节时断电"。测试覆盖：读写删、同一 id 多次覆盖、没变不写、写满后自动整理、整理后旧值都还在、在写入和整理的**每一个字节位置**断电后重新挂载数据都正确（要么是旧值，要么是新值，不会坏）、两个扇区都有效时选对、空白 Flash 自动格式化。

**错卷（计划）**：整理时把已删除的条目也复制了；扇区头先写（整理中断电后旧数据丢失）；读的时候找到第一条就返回（返回的是旧值）；没变也写（擦写次数变多）。
