## 题 6：SPI Flash 驱动 w25q_drv（驱动，难度 3）

### 参照了什么

Winbond 官方数据手册 **W25Q64JV（Revision J，2018-03-27）**[1]。核对过的原文要点：

| 内容 | 原文要点 |
|---|---|
| 容量与分页 | 64M-bit / 8M-byte，32768 页，每页 256 字节；一次最多编程 256 字节；4KB 为一个扇区 |
| 身份 | 读 JEDEC ID 指令 9Fh 返回 3 字节：厂商 EFh，器件 4017h（-IQ/JQ 型号）或 7017h（-IM/JM 型号） |
| 指令码 | 写使能 06h；读数据 03h + 24 位地址；页编程 02h + 24 位地址 + 数据；扇区擦除 20h + 24 位地址；读状态寄存器 1 05h |
| 写使能 | 页编程、扇区擦除之前必须先发写使能；**每次编程或擦除完成后，写使能会自动清掉** |
| 跨页 | "如果最后一个地址字节不为 0，且数据超过本页剩余长度，地址会**回绕到本页开头**"，覆盖前面的数据 |
| 忙标志 | 状态寄存器 bit0 为 BUSY；编程、擦除期间为 1，此时芯片**忽略除读状态以外的指令** |
| 编程只能把 1 变成 0 | 页编程只对"已擦除（FFh）"的位置有效；擦除把整个扇区变回 FFh |
| 时间 | 页编程典型 0.4 ms、最长 3 ms；扇区擦除典型 45 ms、最长 400 ms |

### 怎么用

题目提供 SPI 接口头文件 `hal_spi.h`（锁定），只有一个函数：

> 选中芯片（拉低片选）→ 先发送 tx 的 n 个字节 → 再接收 m 个字节 → 释放片选

★ **一次调用就是一次完整的片选周期**。理由：手册规定编程、擦除指令要在片选拉高后才执行，把片选藏在一次调用里，就不会出现"忘了拉高片选"这类和本题考点无关的错误。

驱动提供：初始化（读身份）、读数据、写数据（自动跨页拆分）、擦除扇区。

### 规则

| 情况 | 应该怎样 | 依据 |
|---|---|---|
| 初始化 | 发 9Fh 读 3 字节；必须是 EF 40 17 或 EF 70 17，否则返回"芯片不对" | [1] 第 8.1 节 |
| 读数据 | 一次发 03h + 3 字节地址（**高字节在前**），接着读 len 字节；len 为 0 直接成功、不碰总线 | [1] 指令表 |
| 地址越界（地址 + 长度 > 8 MB） | 返回"参数错误"，不碰总线 | — |
| 写数据：按页拆分 | 数据跨越 256 字节页边界时，必须拆成多次页编程，每次不跨页 | [1] Page Program 一节 |
| 写数据：每一页之前 | 先发 06h 写使能（因为上一页编程完成后写使能会自动清掉） | [1] 第 7.1 节 |
| 写数据：每一页之后 | 反复读状态寄存器（05h），直到 BUSY = 0 才能继续 | [1] BUSY 一节 |
| ★ 等待忙标志的上限 | 头文件给出最多查询次数（例如 100000 次），超过返回"超时"。理由：题目没有提供延时函数，用次数上限保证不会死等 | 我的选择 |
| ★ 写之前不自动擦除 | 驱动只负责编程；需要先擦除时由调用方调用擦除函数（需求文档里写明"编程只能把 1 变成 0"） | [1]；我的选择 |
| 擦除扇区 | 写使能 → 20h + 地址 → 等 BUSY 清零 | [1] 第 8.3 节 |
| ★ 擦除地址没有 4KB 对齐 | 返回"参数错误"，**不**自动向下对齐（避免擦掉调用方没想到的数据） | 我的选择 |
| SPI 失败 | 立即返回"总线错误" | — |
| 没初始化成功就读写擦 | 返回"参数错误"，不碰总线 | 与 MPU6050 题一致 |

**判卷方式**：隐藏测试带一颗"假 Flash"，按手册行为模拟：没有写使能就忽略编程、编程后自动清写使能、跨页时地址回绕、忙的时候忽略指令、只能把 1 变成 0。

**错卷（计划）**：不按页拆分（跨页数据被回绕覆盖）；只在开头发一次写使能（第二页起写不进去）；不等忙标志就发下一条指令；地址低字节在前。

## 题 7：Modbus RTU 从机 modbus_slave（协议，难度 3，多模块）

### 参照了什么

Modbus 组织官方的两份规范：
- **《MODBUS Application Protocol Specification V1.1b3》**（2012-04-26）[2]
- **《MODBUS over Serial Line Specification and Implementation Guide V1.02》**[3]

核对过的原文要点：

| 内容 | 原文要点 | 出处 |
|---|---|---|
| 功能码 03 读保持寄存器 | 请求：起始地址 2 字节 + 数量 2 字节，数量 1–125（0x7D）；响应：字节数 = 2N，然后每个寄存器高字节在前 | [2] 6.3 节 |
| 功能码 06 写单个寄存器 | 正常响应**原样回显请求** | [2] 6.6 节 |
| 异常响应 | 功能码最高位置 1（加 0x80），后跟 1 字节异常码 | [2] 第 7 节 |
| 异常码 | 01 不支持的功能码；02 地址非法（"起始地址 + 数量"超出范围）；03 数据值非法（包括"隐含长度不对"）；04 设备故障 | [2] 第 7 节 |
| **检查顺序** | 状态图规定：先查功能码（01）→ 再查数量 / 数值（03）→ 再查地址（02）→ 执行出错（04） | [2] 图 13、图 16 |
| 从站地址 | 1–247；0 是广播；248–255 保留 | [3] 2.2 节 |
| 广播 | 广播请求**不回复**，而且广播"必然是写命令" | [3] 2.2 节 |
| CRC | 低字节在前；CRC 错误的帧**丢弃、不回复** | [3] 2.5.1.2 节、2.4.2 节 |
| 地址不是本机 | 丢弃 | [3] 2.5.1.1 节 |
| 帧长度 | RTU 帧最长 256 字节 | [3] 2.5.1 节 |

### 怎么用

★ **调用方负责分帧**，驱动每次收到**一整帧**。理由：RTU 用"3.5 个字符的静默时间"分帧，要靠硬件定时器，和本题的协议逻辑无关；而且"从字节流里切帧"已经由串口收包题考过了。

驱动提供：
- 初始化：本机地址 + 调用方提供的保持寄存器数组；
- 处理一帧：输入请求帧，输出响应帧，返回响应长度（0 表示不回复）。

### 规则

| 情况 | 应该怎样 | 依据 |
|---|---|---|
| 初始化地址不在 1–247，或寄存器数组为空 | 初始化失败 | [3] |
| 帧长度小于 4 或大于 256 | 丢弃，不回复 | [3] |
| CRC 不对 | 丢弃，不回复 | [3] |
| 地址既不是本机也不是 0 | 丢弃，不回复 | [3] |
| 不支持的功能码（03、06 以外） | 回复异常 01 | [2] |
| 03：帧长度不是 8 字节 | 回复异常 03（隐含长度不对） | [2] 第 7 节 |
| 03：数量不在 1–125 | 回复异常 03 | [2] 图 13 |
| 03：起始地址 + 数量超出寄存器个数 | 回复异常 02 | [2] 图 13、第 7 节的 96 + 4 / 96 + 5 例子 |
| 03：正常 | 回复：地址、03、字节数、各寄存器（高字节在前）、CRC | [2] 6.3 节 |
| 06：帧长度不是 8 字节 | 回复异常 03 | [2] 第 7 节 |
| 06：地址超出寄存器个数 | 回复异常 02 | [2] 图 16 |
| 06：正常 | 写入，回复与请求完全相同的帧 | [2] 6.6 节 |
| 广播（地址 0）+ 06 | 执行写入，**不回复** | [3] |
| ★ 广播 + 03（读） | 什么都不做，不回复。规范说广播必然是写命令，没规定收到广播读怎么办，最安全的做法是忽略 | [3]；我的选择 |
| ★ 响应缓冲区不够放 | 若至少放得下 5 字节，回复异常 04（设备故障），**不执行**写入；连 5 字节都放不下就不回复 | [2] 异常码 04；我的选择 |
| 参数为 NULL | 不回复，不崩溃 | — |

### 为什么这道题用来演示多 Agent

它可以自然拆成 3 个以上模块：CRC 计算、帧检查与组装、功能码处理、从机分发。阶段 3 的验收要求"规划结果至少有 3 个模块，没有依赖关系的模块并行执行"，这道题正好满足。

**错卷（计划）**：先查地址后查数量（违反规范的检查顺序）；对广播也回复；响应的 CRC 高字节在前；地址范围差一（最后一个寄存器读不到）。
