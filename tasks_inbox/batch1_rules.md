## 二、第一批规则

### 题 1：中值滤波 median_filter

**用途**：传感器偶尔读出一个离谱的值（比如温度突然跳到 999），中值滤波取最近 5 个读数的"中间那个"，离谱值就被挤掉了。

**怎么用**：调用方提供一个状态结构体；每来一个新读数（-32768 到 32767 的整数）就调用一次"推入"，函数返回当前滤波结果。

| 情况 | 应该怎样 |
|---|---|
| 已经有 5 个读数 | 返回最近 5 个的中位数，即从小到大排好后的第 3 个 |
| 第 6 个读数到来 | 丢掉**最早**的那个，再算最近 5 个的中位数（窗口往前滑） |
| ★ 不足 5 个读数（刚开始） | 用已有的几个算中位数；个数是偶数时取**中间两个里较小的那个**，不取平均（取平均会出现小数和舍入问题） |
| 读数有重复，比如 3, 3, 3, 1, 9 | 正常处理，结果是 3 |
| 读数在两个极端，比如 -32768 和 32767 混着来 | 结果正确，不能溢出（只比较大小，不做加法） |
| 调用"清空" | 回到刚初始化的状态，之前的读数全部作废 |
| 结构体或输出位置传了 NULL | 返回失败，不崩溃 |
| 第一个读数之前就去取结果 | ★ 返回失败（还没有数据） |

**错卷（故意改坏的版本）**：
- 为了求中位数，直接把窗口原地排序，打乱了"谁最早"，之后丢错了读数；
- 窗口只存 4 个；
- 偶数个时取了较大的那个。

### 题 2：软件定时器 soft_timer

**用途**：单片机通常只有一个硬件定时器，每 1 毫秒"嘀嗒"一次（tick）。软件定时器在它上面模拟出 8 个独立的"闹钟"。

**怎么用**：
- 每个闹钟有编号 0–7；
- "启动"时给出周期（多少个 tick）和类型：单次 或 循环；
- 调用方每个 tick 调用一次"嘀嗒"，函数返回**这一个 tick 到点的闹钟有哪些**（每个闹钟占一个二进制位）。

| 情况 | 应该怎样 |
|---|---|
| 启动周期为 3 的单次闹钟 | 之后第 1、2 次"嘀嗒"不响，**第 3 次**响，然后自动停止 |
| 启动周期为 3 的循环闹钟 | 第 3、6、9……次"嘀嗒"响，一直响下去，不能越走越慢 |
| 同一个 tick 有几个闹钟同时到点 | 一次全部报出来 |
| 停止一个闹钟 | 之后不再响；停止本来就没在运行的闹钟也没问题 |
| ★ 闹钟还在运行时再次"启动"它 | 用新周期**从头开始倒数**（不是在原来的基础上累加） |
| ★ 周期给 0 | 拒绝启动，返回失败 |
| 编号不在 0–7 | 拒绝，返回失败 |
| 查询"还剩几个 tick" | 运行中返回剩余数；已停止返回 0 |
| 查询"是否在运行" | 单次闹钟响过之后返回"否" |
| 结构体传 NULL | 各函数返回失败、0 或"否"，不崩溃 |

**错卷**：
- 晚一个 tick 才响；
- 循环闹钟重新装填时差一，越走越慢；
- 单次闹钟响了不停，变成了循环。

### 题 3：串口收包 uart_frame

**用途**：串口一次只来一个字节，收的一方要自己判断"一帧从哪开始、到哪结束、有没有传错"。

**帧格式**（★ 由我定，参考常见私有协议）：

```
0xAA（帧头） | 长度 N（0–64） | N 个字节的数据 | 校验码 2 字节
```

★ 校验码用已有题目 crc16_modbus 里的同一种 CRC-16/MODBUS 算法（实现要自己写在本题里），范围是"长度字节 + 数据"，低字节在前。

**怎么用**：每收到一个字节就调用一次"喂入"，函数返回三种结果之一：没完、收到一帧好的、收到一帧坏的。收到好帧后，可以取出这帧的数据和长度。

| 情况 | 应该怎样 |
|---|---|
| 一帧完整、正确 | 最后一个字节喂入时返回"收到好帧"，取出的数据和长度都对 |
| 帧头之前有杂乱字节 | 忽略，直到遇到 0xAA |
| 两帧紧挨着（粘包） | 两帧都能收到 |
| 一帧分好几次才到齐（半包） | 照常拼起来，因为是一个字节一个字节喂的，天然支持 |
| 校验码不对 | 返回"收到坏帧"，然后重新开始等下一个 0xAA |
| ★ 长度大于 64 | 当场判为坏帧，重新等帧头（不会傻等 200 个字节） |
| ★ 长度为 0 | 合法，是一帧空数据（只有帧头、长度、校验码） |
| ★ 坏帧里面恰好藏着 0xAA | **不回头**重新扫描已经收过的字节，只从下一个新字节开始找帧头。代价：这种情况下可能丢一帧。好处是不用额外开缓冲区 |
| 数据里出现 0xAA | 照常当数据，不会被误认为帧头，因为已经知道长度了 |
| 取数据时还没收到过好帧 | 返回长度 0 |
| 结构体传 NULL | 返回"没完"或失败，不崩溃 |

**错卷**：
- 校验时漏算了长度字节；
- 长度刚好 64 时被误判为太长（差一）；
- 坏帧之后没有回到"等帧头"状态，后面的好帧全收不到。
