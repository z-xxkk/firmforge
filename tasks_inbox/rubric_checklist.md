# 对照赛题一评分细则的自查（2026-11-10）

依据：《关于举办第五届"未来杯"技术大赛的通知》附件 1 赛题 1。逐条对照代码、数据和文档。

图例：✅ 已有且测过 ⚠ 有但不完整，或只在一条流程里有 ❌ 没有

## 一、最重要的发现

**项目其实是两条互不相通的流程：**

| | 旧流程（纯逻辑模块，宿主机测试） | 嵌入式新流程（上板，作品主打） |
|---|---|---|
| 工作流 | 由 TOML 工作流驱动（`orchestrator/engine.py` + `workflows/module_dev.toml`），可在设计器里编辑、试运行 | 写死在 `embedded/flow.py`：规则 → 设计 → 按依赖顺序逐个模块 → 编码、测试 → 检查 → 诊断 |
| 调度 | smart 调度（成功率、成本、负载、探索打分）、DAG 优先级、LLM 和判定并发 | 没有调度器：模块一个接一个跑，编码固定用 coder-strong |
| 经验库（提示词随经验调整） | 有：经验条目放进 Agent 上下文 | 没用 |
| 回滚、升级 | 有 | 有诊断归因分派、规则退回"待核对"；没有回滚 |

细则要求"五模块齐备且**逻辑连贯**"，还要求"编排与调度的智能化，而非简单的硬编码流程"。视频也要求展示"Agent 编排过程、任务调度执行"。现在设计器和调度器只能演示旧流程，主打的上板流程恰好是硬编码的。评委看视频时，看到的会是两段不相干的演示。

## 六、建议的取舍（需要负责人决定）

1. **把嵌入式流程接进编排引擎**（工作流模板 + 调度选编码 Agent + 经验库）。这是让"五模块逻辑连贯"、视频成立的关键，也最费工作量。
2. **仓库改公开**（对外可见的操作，需负责人决定和操作时间）。
3. **补一个不需要板子的复现脚本**。
4. 方案书、PPT、视频按细则章节写。
