## 一、六项核心能力（"该平台应至少支持"）

| 要求 | 现状 | 判断 |
|---|---|---|
| Agent 团队定义与管理：不同角色、**技能、工具集、记忆能力**；动态注册、发现、版本管理 | `agents/*.toml` 有 6 个 Agent，写了角色、模型档位、提示词、擅长的题型；注册表支持注册、注销、按角色查找、多版本共存。但 Agent 定义里**没有"工具集"和"记忆能力"两项**；也没有命令能列出已注册的 Agent | ⚠️ |
| 工作流编排：顺序、并行分支、条件判断、循环迭代、子工作流嵌套 | `workflows/module_dev.toml` 用 TOML 写流程，7 种节点（agent、verify、parallel、condition、loop、foreach/subflow、human）全覆盖；赛题允许"代码化"，可视化不是必须 | ✅ |
| 智能调度：按任务特征、负载、依赖、优先级动态分配；至少一种自我循环 | smart 策略按成功率、成本、负载、探索打分；关键路径优先；修正循环 + 升级阶梯 | ✅ |
| **工具与外部系统集成：通过 MCP、Function Calling、API 插件等方式集成外部工具** | 编译器、cppcheck、单元测试是**平台自己调用的**，Agent 不能主动调用工具；LLM 接口支持传 tools 参数但**没有任何地方用到**；MCP 服务原计划为"可选"，**没写** | ❌ |
| 执行监控与结果验证：状态监控、中间结果、异常检测、自动 / 人工验证节点、交叉验证或基准比对 | 事件流、每次尝试的快照、5 层判定器、人工确认节点、测试 Agent 与编码 Agent 互相校验、隐藏测试作为基准比对 | ✅ |
| 反馈与自我优化：按验证结果调整提示词、工具选择或工作流路径 | 经验库写进后续提示词、升级阶梯换 Agent、重新规划（改工作流路径） | ✅ |
