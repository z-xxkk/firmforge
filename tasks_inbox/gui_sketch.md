## 一、参考了谁、借了什么

| 参考对象 | 看到的做法（一手资料） | 我们借来的 |
|---|---|---|
| **DeepSeek Harness**（DeepSeek 官方开源，GitHub deepseek-ai/deepseek-harness，文档 docs/user/guide） | 设置分"通用设置、模型、内置插件、Agent 预设"；模型页按提供商分卡片，**密钥只写不读**（保存后只显示脱敏描述）；设置页右上角"打开配置文件"，**网页改的就是同一份配置文件**；外部 MCP 工具以 `mcp__服务名__工具名` 的名字出现；MCP 子进程断了会自动重连 | 设置页结构、密钥只写、"打开配置文件"、MCP 工具命名和重连 |
| **Hermes Agent**（Nous Research，官方文档 configuration 页） | 配置放 `config.yaml`，密钥放 `.env`，"非密钥设置以配置文件为准"；对话里用 `/model`、`/reasoning` 切换型号和思考强度；工具按"工具集"分组开关；记忆写入可以要求人工批准 | 配置文件 + `.env` 分开（我们已经是这样）；输入框支持斜杠命令；工具分组；外部工具"调用前问我" |
| **DeepSeek 接口文档**（思考模式页） | 思考模式默认开，强度 `reasoning_effort` 取 low / high / max，默认 high；`thinking: disabled` 关闭 | 思考强度四档：关、低、高、最高 |
| 主流聊天式 Agent（Claude、ChatGPT、Cursor 等的通行做法） | 左边会话列表 + "新对话"；输入框下方放型号和思考强度；`@` 引用文件或对象 | 同左 |
| **Qt Designer**（Qt 官方的可视化界面设计器） | 左"控件箱"、右"对象查看器 + 属性编辑器"；画好的界面存成 `.ui` 文件（XML），再由 uic 转成代码；可以直接"查看代码" | 设计器四块布局一一对应；画布存成工作流文件；下方实时显示代码 |

## 四、工作流设计器（[gui_designer.png](gui_designer.png)）

### 和 Qt Designer 的对应关系

| Qt Designer | 我们的设计器 |
|---|---|
| 控件箱（Widget Box） | 左：**步骤箱**，按"干活 / 控制 / 嵌套"分组 |
| 窗体编辑区 | 中：**画布**（原理图风格） |
| 对象查看器（Object Inspector） | 右上：**步骤树**，主流程和每个子流程的层级 |
| 属性编辑器（Property Editor） | 右下：**属性表**，左列名字、右列可改的值 |
| `.ui` 文件 + "查看代码" | 下：**`workflows/*.toml` 实时代码视图**，改画布代码跟着变，改代码画布跟着变 |
| uic 把 `.ui` 编译成代码 | 引擎读 TOML 执行；同一份 TOML 也按第六节的格式交给 AI |

### 它要做到的事

1. 拖拽画流程、连线、删除，子流程可以展开或双击进入。
2. 属性表改每一步的设置（Agent 步骤可指定角色或具体某个 Agent、循环上限和停止条件、条件判断依据、人工确认何时出现）。
3. 保存前检查：没连上、循环没上限、没有可用 Agent、引擎不支持的组合，标在图上，不让保存。
4. 版本：保存成新版本号，旧版保留，和 1.0.0 的差别列在右下。
5. **"让 AI 改…"**：选中几个步骤（或不选），输入一句话，例如"审查之后加一步人工验收"。AI 收到的是第六节格式的任务单（意图 + 选中步骤的 TOML），回一份新的 TOML；设计器把差别标成绿色给你看，你点"接受"才生效，同样要过保存前检查。对话框里打 `/workflow 审查之后加人工验收` 走的是同一条路。
6. 试运行：用当前版本跑一道题，跳到对话。

| 分类 | 内容 |
|---|---|
| 通用 | 语言、主题（浅 / 深 / 跟随系统）、默认后端（docker / 本机）、默认配置、运行目录 |

| **工具与 MCP** | 内置工具开关；外部 MCP 服务列表（启动方式、状态、提供的工具、调用前问我、启用）；把 FirmForge 当 MCP 服务给别人用的配置片段和自检按钮 |

```
## 引用
每条引用一个带标签的块，原样给出它的"代码"：
[workflow.step repair]   → 这一步的 TOML
[module pdu]             → 规划里这个模块的职责和接口
[file src/pdu.c]         → 文件内容
[diagnosis pdu#1]        → 诊断结论

## 约束
芯片、资源预算、禁止的函数、不能改的头文件……

## 附件
需求文档、公共头文件、上一次的检查报告……
```

**为什么这样设计**
- 画布上的东西本来就是 TOML 代码（第四节），引用它就是贴它的代码，和贴一个 `.c` 文件是一样的待遇。所以"可视化"和"打字"在 AI 那边看起来没有区别，只有"意图"那一句的来源不同。
- 每次调用的任务单都存进运行记录，界面上"发给 AI 的内容"直接显示，答辩时能逐条说明 AI 在每一步看到了什么（赛题要求的"人工智能使用说明"）。
- 各角色的提示词文件（`prompts/*.md`）只写"你是谁、怎么做"，具体任务一律走任务单。
- **代价**：现有提示词的拼装方式要改成这个格式，Agent 看到的内容变了，阶段 5 的评测要重跑（加工具时本来就要重跑）。
