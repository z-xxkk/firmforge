# 设计决定记录

答辩时被问到"为什么这样设计"，答案就在这里。每条决定都写明是谁定的、理由是什么。

状态说明：
- **已定**：项目负责人明确做出的决定；
- **默认**：设计文档采用的方案，负责人还没有明确表态，可以推翻。

Claude Code 实现过程中由负责人新拍板的决定，按同样格式追加在表格末尾。

| 12 | 2026-10-23 | 快照用"每次尝试一个目录"，不用 git commit | 多个模块并行时同时往一个 git 仓库提交会冲突；Windows 不用额外装 git；回滚就是复制最好的那次尝试 | 默认 |
| 13 | 2026-10-23 | 经验库和知识库用 BM25 关键词检索，不用向量库 | DeepSeek 不提供 embedding 接口；数据量小，关键词检索够用；检索模块可单独替换 | 默认 |
| 14 | 2026-10-23 | 审查 Agent 只作提示，最多触发 1 次额外修正，不能阻止通过 | 主观意见不作为通过依据；控制成本 | 默认 |
| 15 | 2026-10-23 | 桌面软件默认在 Docker 里运行核心，通过事件文件实时显示；演示视频用回放模式录 | 本机不需要装工具链；不怕现场 LLM 输出不稳定 | 默认 |
| 16 | 2026-10-23 | 阶段 1 先在开发机上用本机 gcc 实现和测试，交叉编译、资源预算、cppcheck 留到 Docker 里验收；任务预算先填估计值，再用容器里 `check-task` 的实测值校准 | 开发机还没装 Docker、arm-none-eabi-gcc 和 cppcheck；不改动系统包；缺工具的层照规则标 skipped，不会误判通过 | 已定 |
| 17 | 2026-10-23 | 任务头文件直接公开结构体字段（注释写明"实现私有"），不用不透明存储块 | 调用方不能 malloc，必须知道结构体大小；公开字段简单、测试易读，不透明存储要处理对齐、Agent 更容易出错。代价是 Agent 的实现被字段限定 | 已定 |
| 18 | 2026-10-23 | 附录 B 之外补充的 7 条边界规则照现行定：ringbuf 空时读不改 `*out`、out 为 NULL 不取走数据、clear(NULL) 不动作；crc16 append 只改末尾 2 字节、查表须 const；debounce init(NULL) 不动作 | 负责人审核隐藏测试清单后确认；每条都写进了 spec.md，Agent 能看到，隐藏测试不考 spec 之外的行为 | 已定 |
