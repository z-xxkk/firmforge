# 最后一轮测试方案（初赛缩小版，DECISIONS 第 119 条）

负责人 2026-11-14 定的大方向：先测出现在的通过率，针对性地改进 Agent，再测一次做前后对比；智能调度要靠测试数据来学；
初赛先做缩小版（完整的调度对比留到决赛）；最终测试精简为 3 种配置；另外 5 道题做调优题、原来 6 道做测试题。
具体题目、次数、指标由 Claude Code 定（本文件），负责人审核。

## 1. 依据（一手资料）

| 资料 | 采用的做法 |
|---|---|
| Miller，[Adding Error Bars to Evals](https://arxiv.org/abs/2411.00640)（Anthropic，2024） | 通过率带标准误；同一题的多次运行相关，标准误按题聚类计算；前后对比在同一批题上逐题配对 |
| Olausson 等，[Is Self-Repair a Silver Bullet for Code Generation?](https://arxiv.org/abs/2306.09896)（ICLR 2024） | 把花费算进比较（每通过一次花多少钱）；修正效果的瓶颈是反馈质量，所以优先改"自检"（Agent 自己写的测试） |
| Zhu 等，[Establishing Best Practices for Building Rigorous Agentic Benchmarks](https://arxiv.org/abs/2507.02825)（NeurIPS 2025） | 方案书里按题目有效性、判定有效性、结果报告三方面逐条说明（标准答案自检、变异体、隐藏测试隔离、跳过不算通过） |
| Yao 等，[τ-bench](https://arxiv.org/abs/2406.12045)（2024） | 加报 pass^k：同一题 k 次都通过的比例（稳定性） |
| [AFlow](https://arxiv.org/abs/2410.10762)（ICLR 2025）、[DSPy 优化器文档](https://dspy.ai/learn/optimization/optimizers) | 调优只看调优题，最后在没看过的测试题上报分；题少时最容易过拟合 |
| Zhao 等，[ExpeL](https://arxiv.org/abs/2308.10144)（AAAI 2024） | 经验库在调优题上积累，测试时冻结使用，看经验能不能迁移到没见过的题 |
| [RouteLLM](https://arxiv.org/abs/2406.18665)（ICLR 2025）、[BaRP](https://arxiv.org/abs/2510.07429)（2025） | 调度看"花多少钱拿回强模型多少水平"；按历史结果在线学习（我们的打分是 UCB 式：成功率 − 成本 − 负载 + 探索） |

## 2. 上一轮数据里看到的问题（11/08，results/board_full）

- 36 次多 Agent 运行里，有 12 次**流程自己判"没通过"、交付的代码却过了隐藏测试**：Agent 自己写的测试有错或编译不过，把 4 次机会用完。
- 也有反过来的：rmt_pulse_meter 多次流程判通过、隐藏测试没过（Agent 自己的测试太松）。
- 所以短板是自检（反馈质量），和 Self-Repair 那篇的结论一致。这类问题在平台自己的运行记录里就看得到，改它不需要看隐藏测试。
- 11/08 之后评测路径改过不少（编码和写测试并行、接线、软复位等），旧数据不能当基线，基线要重跑。

## 3. 题目划分和纪律

| 用途 | 题目 | 说明 |
|---|---|---|
| 调优题（5 道） | gpio_edge_count、gptimer_tick、i2c_bus_scan、imu_uart_logger、uart_loopback | 从没正式评测过。改提示词、调度器学习、攒经验都只在这 5 道上做 |
| 测试题（6 道） | ledc_pwm、max30102_fifo、max30102_temp、mpu6050_drdy、mpu6050_drv_idf、rmt_pulse_meter | 只在"改进前"和"改进后"各测一次；调优期间不看它们的逐个用例结果，只看汇总 |

纪律（写进方案书）：
1. 改进只能依据平台自己能看到的信息（运行记录、编译输出、Agent 自己的测试结果、流程结论和隐藏测试是否一致的**汇总比例**），不依据隐藏测试的具体用例内容。
2. 只做对所有题都成立的改进，不写针对某道题、某个器件的特例。
3. 前后两次的结果都如实报告，没变好的也写。
4. 两批题难度不同（调优题多是难度 1–2，测试题多是 3），方案书里说明。

## 4. 三种配置

| 配置 | 内容 | 前后都跑？ |
|---|---|---|
| single | 单 Agent，不给规则、不写测试，只把编译错误反馈给它（和上一轮定义相同） | 只在基线跑一次（这条路径不受改进影响），前后对比共用 |
| none | 多 Agent：编码、测试、诊断分工，修正循环，不给规则库；所有 Agent 快档 | 前后都跑 |
| full | 多 Agent 完整版：已确认规则库 + 智能调度（编码 Agent 在 coder-fast 快档和 coder-strong 强档之间由调度器挑）+ 经验库；其他 Agent 快档 | 改进前跑它的前身 verified（同样的规则库，编码固定、不调度、无经验），改进后跑 full |

原来的 unverified（未核对规则）不再跑；上一轮的数据保留在 results/board_full，方案书里照常引用。

## 5. 步骤

| 阶段 | 内容 | 次数 | 花费上限 |
|---|---|---|---|
| 0 准备 | 补 gptimer、uart 的已确认规则（调优题要用，`firmforge rules build --scopes gptimer,uart --tier fast --think low`，负责人确认）；`firmforge check-board-tasks` 自检 11 道题 | — | 约 0.2 元 |
| 1 基线 | 测试题 × single、none、verified × 3 次 | 54 | 15 元 |
| 2 调优 | 调优题 × none、full × 2 次；看汇总找原因、做通用改进，最多两轮。调度器的成绩和经验库写进这次实验自己的数据库，不碰平时用的 | ≤ 40 | 10 元 |
| 3 复测 | 测试题 × none、full × 3 次；full 用调优阶段学到的成绩和经验，**冻结**（测试时不再学习） | 36 | 12 元 |

每次运行约 5 分钟，板子一次只能跑一个，合计约 11 小时板子时间。基线可以夜里挂着跑。

## 6. 指标

每种配置报：
- **通过率**（隐藏测试判定，跳过的不算）± 按题聚类的标准误；
- **前后对比**：同一道题改进前后逐题配对的差值和它的标准误；
- **稳定性 pass^3**：同一题 3 次都通过的题占比；
- **自检准确率**：流程自己的结论和隐藏测试一致的比例（多 Agent 配置）；
- **收敛速度**：通过的运行平均用了几次尝试；
- **每通过一次的花费**（元）和平均用时；
- full 另报：调度器把多少次编码交给了强档、交给强档后的通过率，以及用了经验库的次数。
