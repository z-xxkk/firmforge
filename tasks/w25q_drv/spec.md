# W25Q64 SPI Flash 驱动 w25q_drv

实现 `include/w25q.h` 中声明的全部函数：通过 SPI 识别 W25Q64JV、读数据、写数据、擦除扇区。

## 约束

- 不能使用动态内存、标准输入输出函数，不能用递归。
- 只能通过 `include/hal_spi.h` 里的 `hal_spi_transfer` 访问芯片，不能自己实现它（由使用方提供；写单元测试时请在 `tests/` 里自己写一个模拟实现）。
- 两个头文件都由任务锁定，不能修改。

## SPI 接口

`hal_spi_transfer(tx, tx_len, rx, rx_len)`：**一次调用就是一次完整的片选周期**——拉低片选，先发送 `tx` 的 `tx_len` 个字节，再接收 `rx_len` 个字节到 `rx`，最后拉高片选。返回 `HAL_SPI_OK` 或 `HAL_SPI_ERROR`。

## 芯片资料（摘自 Winbond《W25Q64JV 数据手册》Revision J）

| 内容 | 说明 |
|---|---|
| 容量 | 8 MB（8388608 字节），每页 256 字节，每个扇区 4096 字节 |
| 读身份 9Fh | 返回 3 字节：厂商 EFh，器件 40h 17h（-IQ/JQ）或 70h 17h（-IM/JM） |
| 读数据 03h | 发送 03h + 3 字节地址（A23–A16、A15–A8、A7–A0，**高字节在前**），之后连续读出数据 |
| 写使能 06h | 页编程、扇区擦除之前必须先执行；**每次编程或擦除完成后自动清除** |
| 页编程 02h | 发送 02h + 3 字节地址 + 1–256 字节数据。**如果数据超过本页剩余长度，地址会回绕到本页开头**，覆盖前面的数据。只能把 1 改成 0（应在已擦除为 FFh 的位置编程） |
| 扇区擦除 20h | 发送 20h + 3 字节地址，把该地址所在的 4KB 扇区全部变回 FFh |
| 读状态寄存器 05h | 返回 1 字节：bit0 = BUSY（编程或擦除进行中为 1），bit1 = WEL（写使能） |
| 忙 | BUSY = 1 期间，芯片**忽略除读状态寄存器以外的所有指令** |
| 时间 | 页编程最长 3 ms，扇区擦除最长 400 ms |

## 函数行为

| 函数 | 正常行为 | 异常 / 边界 |
|---|---|---|
| `w25q_init(dev)` | 读身份，是 EF 40 17 或 EF 70 17 就进入就绪状态，返回 `W25Q_OK` | dev 为 NULL：`W25Q_ERR_PARAM`；身份不对：`W25Q_ERR_ID`；SPI 失败：`W25Q_ERR_BUS`。任何失败后都处于未就绪状态 |
| `w25q_read(dev, addr, buf, len)` | 用**一次** 03h 读出 len 字节 | len 为 0：直接返回成功，不访问 SPI |
| `w25q_write(dev, addr, data, len)` | 按下面的步骤写入 | len 为 0：直接返回成功，不访问 SPI |
| `w25q_erase_sector(dev, addr)` | 写使能 → 20h + 地址 → 等待不忙 | addr 不是 4096 的整数倍：`W25Q_ERR_PARAM`，**不自动对齐** |

写入步骤：把数据按 256 字节页边界拆成若干段（每段不跨页），对每一段依次：
1. 发写使能 06h；
2. 发页编程 02h + 地址 + 这一段数据；
3. 反复读状态寄存器，直到 BUSY = 0。

写入**不会**自动擦除；需要擦除时由调用方先调用 `w25q_erase_sector`。

等待 BUSY 时最多读 `W25Q_MAX_BUSY_POLLS` 次状态寄存器，仍然忙就返回 `W25Q_ERR_TIMEOUT`。

通用规则：
- dev、buf、data 为 NULL，驱动未就绪，或 `addr + len` 超出 8 MB：返回 `W25Q_ERR_PARAM`，不访问 SPI；
- 任何一次 SPI 调用失败：立即返回 `W25Q_ERR_BUS`，不再进行后续操作。
