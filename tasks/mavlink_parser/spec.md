# MAVLink 解析器 mavlink_parser

实现 `include/mavlink_parser.h` 中声明的全部函数：从串口字节流里解析 MAVLink v1 和 v2 帧（无人机与地面站之间最常用的通信协议）。

## 约束

- 不能使用动态内存、标准输入输出函数，不能用递归。
- 头文件由任务锁定，不能修改。

## 用法

- `mavlink_parser_init(p, table, count)`：绑定调用方提供的**消息表**。每一项是一种消息的消息号、完整负载长度、CRC_EXTRA（真实系统里由代码生成器产出）。消息表在解析器使用期间必须一直有效。
- `mavlink_parser_feed(p, byte)`：每收到一个字节调用一次，返回本次的结果（见下）。
- `mavlink_parser_message(p)`：返回**最近一条好消息**；还没收到过好消息返回 NULL。这条消息一直保留到下一条好消息到来或重新初始化，坏帧不会清掉它。
- `mavlink_parser_stats(p, &out)`：取统计数字。

## 帧格式（摘自 MAVLink 官方文档《Packet Serialization》）

**v1**（8–263 字节）

| 位置 | 内容 |
|---|---|
| 0 | 起始字节 FEh |
| 1 | 负载长度 n |
| 2 | 序号 |
| 3 | 系统号 |
| 4 | 组件号 |
| 5 | 消息号（1 字节） |
| 6 … n+5 | 负载 |
| n+6、n+7 | 校验，**低字节在前** |

**v2**（12–280 字节）

| 位置 | 内容 |
|---|---|
| 0 | 起始字节 FDh |
| 1 | 负载长度 n |
| 2 | 不兼容标志（01h = 带签名） |
| 3 | 兼容标志（不认识也可以忽略） |
| 4 | 序号 |
| 5 | 系统号 |
| 6 | 组件号 |
| 7、8、9 | 消息号（3 字节，**低字节在前**） |
| 10 … n+9 | 负载 |
| n+10、n+11 | 校验，低字节在前 |
| n+12 … n+24 | 签名（13 字节，只有带签名时才有） |

**校验**：CRC-16/MCRF4XX，初值 FFFFh。计算范围是除起始字节和签名以外的全部字节（从"负载长度"到负载最后一个字节），**再加上该消息的 CRC_EXTRA 一个字节**（只参与计算，不在线上传输）。逐字节的算法与官方 C 参考实现相同：

```c
uint8_t tmp = data ^ (uint8_t)(crc & 0xFF);
tmp ^= (uint8_t)(tmp << 4);
crc = (crc >> 8) ^ (tmp << 8) ^ (tmp << 3) ^ (tmp >> 4);
```

核对用的数值："123456789" 的结果是 6F91h；HEARTBEAT 消息的消息号 0、负载 9 字节、CRC_EXTRA 50。

**v2 负载截断**：发送方会去掉负载末尾的 0 字节（第一个字节不去），所以 v2 帧的长度可以比完整长度短。接收方要在末尾补 0，补到完整长度后再交给调用方。v1 不截断，长度固定。

## 判定规则

一帧收齐（按长度字段和签名标志算出总长）之后，按下面的顺序判定：

| 顺序 | 情况 | 结果 |
|---|---|---|
| 1 | v2 的不兼容标志含 01h 以外的位 | `MAVLINK_BAD_FLAGS`，丢弃 |
| 2 | 消息号不在消息表里 | `MAVLINK_UNKNOWN_MSG`，丢弃（不知道 CRC_EXTRA 就无法验证） |
| 3 | v1 长度不等于消息表长度；v2 长度为 0 或大于消息表长度 | `MAVLINK_BAD_LEN`，丢弃 |
| 4 | 校验不对 | `MAVLINK_BAD_CRC`，丢弃 |
| 5 | 以上都没问题 | `MAVLINK_OK`，更新"最近一条好消息" |

其他规则：

| 情况 | 应该怎样 |
|---|---|
| 等起始字节时收到 FEh、FDh 以外的字节 | 跳过，返回 `MAVLINK_NONE` |
| 帧还没收齐 | 返回 `MAVLINK_NONE` |
| 带签名的 v2 帧 | 读完 13 字节签名才算收齐；签名内容不验证；`is_signed` 为 true |
| 好消息的字段 | `version` 为 1 或 2；`len` 为消息表里的完整长度；`payload` 前 n 字节是收到的负载，其余补 0 |
| 坏帧之后（重新同步） | 丢掉这个坏帧的起始字节，从它的**下一个字节**开始，在已经收到的字节里重新找 FEh 或 FDh，找到就当作新帧的开始继续接收；找不到就回到等起始字节 |
| 重新同步时，已收到的字节里恰好凑成了一帧完整的好帧 | 这次调用返回 `MAVLINK_OK`（交付好帧优先于报告错误）；没有凑成好帧时，返回第一个坏帧的错误 |
| p 为 NULL | `feed` 返回 `MAVLINK_NONE`，`message` 返回 NULL；`stats` 把 out 全部置 0；out 为 NULL 时什么都不做 |
| `init` 的 p 或 table 为 NULL、count 为 0 | 返回 false |
| 消息表里同一个消息号出现多次 | 用第一项 |

## 统计

| 字段 | 含义 |
|---|---|
| `received` | 好消息的条数 |
| `bad_crc` | 校验错的帧数 |
| `dropped` | 因 `BAD_FLAGS`、`UNKNOWN_MSG`、`BAD_LEN` 丢弃的帧数 |
| `lost` | 按序号推算丢失的消息数：同一系统号 + 组件号的两条好消息，序号之差减 1 累加进来（序号 255 之后是 0，差值按 8 位无符号计算） |

丢包统计最多跟踪 `MAVLINK_MAX_SOURCES`（8）个"系统号 + 组件号"来源，超过的来源不统计；某来源的第一条消息不算丢包。重新同步时发现的坏帧也照常计数。

## 例子

v1 HEARTBEAT（序号 0、系统号 1、组件号 1，负载 `00 00 00 00 02 03 51 04 03`）：

```
FE 09 00 01 01 00  00 00 00 00 02 03 51 04 03  7D DD
```

同样的消息用 v2 发送（序号 7）：

```
FD 09 00 00 07 01 01 00 00 00  00 00 00 00 02 03 51 04 03  A4 AC
```
