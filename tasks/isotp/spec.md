# ISO-TP 传输层 isotp

实现 `include/isotp.h` 中声明的全部函数：ISO 15765-2（ISO-TP）在经典 CAN 上的接收和发送。汽车诊断（UDS）用它把最长 4095 字节的消息拆成多个 8 字节的 CAN 帧传输。

## 约束

- 不能使用动态内存、标准输入输出函数，不能用递归。
- 头文件由任务锁定，不能修改。
- 只做经典 CAN（每帧最多 8 字节）、普通寻址；不做 CAN FD 和 32 位长度。

## 用法：事件驱动

模块**不自己计时、不直接收发 CAN**：
- 接收：每收到一帧 CAN 就调用 `isotp_rx_frame`；它告诉调用方"需要回一帧流控（`fc_out`）"、"收完一条消息"或"出错了"。等连续帧超时（标准里的 N_Cr）由调用方计时，到时调用 `isotp_rx_timeout`。
- 发送：`isotp_tx_start` 给出第一帧；收到对方的流控帧就调用 `isotp_tx_fc`；状态为 `ISOTP_TX_SENDING` 时反复调用 `isotp_tx_next` 取连续帧，每帧附带"发这一帧之前至少要等多少微秒"。等流控超时（N_Bs）由调用方计时，到时调用 `isotp_tx_timeout`。

## 帧格式（第 1 字节高 4 位是帧类型）

| 帧 | 第 1 字节 | 第 2 字节 | 第 3 字节 | 其余 |
|---|---|---|---|---|
| 单帧 | 0h + 数据长度（1–7） | 数据 | … | 数据 |
| 首帧 | 1h + 总长度的高 4 位 | 总长度的低 8 位 | 数据（共 6 字节） | |
| 连续帧 | 2h + 序号（0–15） | 数据（最多 7 字节） | … | |
| 流控 | 3h + 状态（0 继续发送、1 等待、2 溢出） | 块大小 | 最小间隔 | |

- 首帧的总长度是 12 位，范围 8–4095。首帧必须是满 8 字节的帧。
- 连续帧的序号：首帧之后的第一个连续帧是 1，每帧加 1，15 之后回到 **0**。
- 块大小：0 表示之后的连续帧全部发完、不再等流控；大于 0 表示每发这么多个连续帧，就要等对方再发一帧"继续发送"流控。
- 最小间隔（两个连续帧之间至少隔多久）：00h–7Fh 表示 0–127 毫秒；F1h–F9h 表示 100–900 微秒；其他值是保留值，按 7Fh（127 毫秒）处理。

## 接收规则

`isotp_rx_init(rx, buf, cap, block_size, st_min)`：绑定接收缓冲区，block_size、st_min 是本端回流控时填的值。rx、buf 为 NULL 或 cap 为 0 返回 false。

| 收到 | 应该怎样 |
|---|---|
| 单帧，长度 1–7 且不超过本帧实际字节数（dlc − 1）、不超过缓冲区 | 数据写到缓冲区开头，返回 `ISOTP_RX_DONE` |
| 单帧，长度为 0、超过 dlc − 1 或超过缓冲区 | 忽略，返回 `ISOTP_RX_NONE` |
| 首帧，dlc 不是 8，或总长度小于 8（包括 0） | 忽略 |
| 首帧，总长度超过缓冲区 | `fc_out` 填"溢出"流控，返回 `ISOTP_RX_ERR_OVERFLOW`，不接收 |
| 首帧，其他情况 | 保存前 6 字节，`fc_out` 填"继续发送"流控（本端的块大小和最小间隔），返回 `ISOTP_RX_SEND_FC`，之后等序号 1 的连续帧 |
| 连续帧，但当前没在接收 | 忽略 |
| 连续帧，序号不对 | 放弃这次接收，返回 `ISOTP_RX_ERR_SEQ` |
| 连续帧，还不是最后一帧却不足 8 字节；或最后一帧的数据不够 | 放弃这次接收，返回 `ISOTP_RX_ERR_FORMAT` |
| 连续帧，正常 | 保存数据（最后一帧只取需要的字节，忽略填充）。收齐了返回 `ISOTP_RX_DONE`；块大小不为 0 且本块收满了，`fc_out` 填"继续发送"流控并返回 `ISOTP_RX_SEND_FC`；否则返回 `ISOTP_RX_NONE` |
| 接收进行中又来一个合格的单帧或首帧 | 放弃当前接收（"被打断"次数加 1），按新的单帧 / 首帧处理 |
| 流控帧、帧类型 4h–Fh | 忽略 |
| rx、data、fc_out 为 NULL，dlc 为 0 或大于 8 | 忽略 |

- `fc_out` 只在返回 `ISOTP_RX_SEND_FC` 或 `ISOTP_RX_ERR_OVERFLOW` 时有意义：3 字节流控 + 5 字节填充 CCh。
- `isotp_rx_timeout`：正在接收时放弃这次接收并返回 `ISOTP_RX_ERR_TIMEOUT`，否则返回 `ISOTP_RX_NONE`。
- `isotp_rx_length`：最近一条收完的消息的长度（数据在缓冲区开头）；还没有收完过返回 0。出错或被打断不会清掉它的值，但缓冲区内容可能已被新数据覆盖。
- `isotp_rx_interrupted`：被打断的次数。

## 发送规则

`isotp_tx_init(tx)` 之后状态为 `ISOTP_TX_IDLE`。

| 情况 | 应该怎样 |
|---|---|
| `isotp_tx_start`，长度 1–7 | `frame_out` 为单帧（补满 8 字节），状态直接变为 `ISOTP_TX_DONE`，返回 true |
| `isotp_tx_start`，长度 8–4095 | `frame_out` 为首帧（含前 6 字节），状态变为 `ISOTP_TX_WAIT_FC`，返回 true |
| `isotp_tx_start`，长度为 0 或超过 4095，任何指针为 NULL，或状态是 `WAIT_FC` / `SENDING`（上一条没发完） | 返回 false，什么都不改 |
| 状态不是 `WAIT_FC` 时收到流控，或收到的不是流控帧 | 忽略 |
| 流控帧不足 3 字节 | 状态变为 `ISOTP_TX_ERR_FC` |
| 流控"继续发送" | 状态变为 `ISOTP_TX_SENDING`。块大小和最小间隔以本次发送收到的**第一帧"继续发送"**为准，之后的"继续发送"只用来放行下一块 |
| 流控"等待" | 继续等下一帧流控 |
| 流控"溢出" | 状态变为 `ISOTP_TX_ERR_OVERFLOW` |
| 流控状态 3h–Fh | 状态变为 `ISOTP_TX_ERR_FC` |
| `isotp_tx_next`，状态为 `SENDING` | `frame_out` 为下一个连续帧（序号见上；最后一帧补满 8 字节），`*delay_us` 为发这一帧之前要等的微秒数：每收到一帧"继续发送"后的第一个连续帧为 0，其余为最小间隔。发完最后一帧状态变为 `ISOTP_TX_DONE`；块大小不为 0 且本块发满了，状态变为 `ISOTP_TX_WAIT_FC`。返回 true |
| `isotp_tx_next`，状态不是 `SENDING`，或参数为 NULL | 返回 false |
| `isotp_tx_timeout`，状态为 `WAIT_FC` | 状态变为 `ISOTP_TX_ERR_TIMEOUT`；其他状态下不做任何事 |

发出的所有帧都是 8 字节，没用到的字节填 CCh。发送期间调用方的数据必须保持有效。状态为 `DONE` 或任何错误状态时，可以直接开始下一条。

## 例子（发送 30 字节 00h…1Dh，对方块大小 2、最小间隔 05h）

```
发送方 → 10 1E 00 01 02 03 04 05     首帧：总长度 01Eh = 30，数据 00–05
接收方 → 30 02 05 CC CC CC CC CC     继续发送，块大小 2，最小间隔 5 毫秒
发送方 → 21 06 07 08 09 0A 0B 0C     序号 1，等 0 微秒
发送方 → 22 0D 0E 0F 10 11 12 13     序号 2，等 5000 微秒；本块发满 → 状态 WAIT_FC
接收方 → 30 02 05 CC CC CC CC CC     接收方收满一块，再回一帧继续发送
发送方 → 23 14 15 16 17 18 19 1A     序号 3，等 0 微秒
发送方 → 24 1B 1C 1D CC CC CC CC     序号 4，等 5000 微秒；最后一帧补 CC → 状态 DONE
```
