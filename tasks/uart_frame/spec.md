# 串口帧接收状态机 uart_frame

实现 `include/uart_frame.h` 中声明的全部函数。串口每次只收到一个字节，接收方要自己判断一帧从哪里开始、到哪里结束、有没有传错。

## 约束

- 不能使用动态内存和标准输入输出函数，不能用递归。
- 状态结构体由调用方提供；字段由头文件给出，实现只能使用这些字段，头文件不能修改。
- CRC 计算要自己在本模块里实现。

## 帧格式

```
0xAA（帧头） | N（长度，0–64） | N 个数据字节 | CRC 低字节 | CRC 高字节
```

- CRC 采用 CRC-16/MODBUS：初值 0xFFFF，反射多项式 0xA001，无最终异或（"123456789" 的 CRC 为 0x4B37）。
- CRC 的计算范围是**长度字节加上全部数据字节**（不含帧头）。
- 一帧最长 1 + 1 + 64 + 2 = 68 字节。

## 用法

每收到一个字节调用一次 `uart_frame_feed`，返回三种结果之一：

- `UART_FRAME_NONE`：还没收完，或者在等帧头；
- `UART_FRAME_OK`：刚好收完一帧校验正确的帧；
- `UART_FRAME_ERROR`：发现一帧坏帧。

收到好帧后，用 `uart_frame_payload` 取出数据。

## 接收规则

| 情况 | 应该怎样 |
|---|---|
| 正确的帧 | 前面的字节都返回 NONE，最后一个 CRC 字节返回 OK |
| 等帧头时收到不是 0xAA 的字节 | 忽略，返回 NONE |
| 两帧紧挨着（粘包） | 两帧都能收到 |
| 数据里出现 0xAA | 照常当作数据（长度已知，不会误认为帧头） |
| 长度为 0 | 合法，是一帧空数据 |
| 长度大于 64 | 在收到长度字节时**立刻**返回 ERROR，不再等后面的字节 |
| CRC 不对 | 收到最后一个 CRC 字节时返回 ERROR |
| 出错之后（重新同步） | 丢掉这个坏帧的帧头，从它的**下一个字节**开始，在已经收到的字节里重新找 0xAA，找到就当作新帧的开始继续接收；找不到就回到等帧头状态 |
| 重新同步时，已收到的字节里恰好凑成了一帧完整的好帧 | 这次调用返回 OK（交付好帧优先于报告错误） |

## 函数行为

| 函数 | 正常行为 | 异常 / 边界 |
|---|---|---|
| `uart_frame_init(rx)` | 回到等帧头状态，没有可取的数据 | rx 为 NULL：什么都不做 |
| `uart_frame_feed(rx, byte)` | 见上表 | rx 为 NULL：返回 NONE |
| `uart_frame_payload(rx, &data)` | 返回**最近一帧好帧**的数据长度，并让 `*data` 指向这些数据。这份数据一直保留，直到下一帧好帧到来或重新初始化；坏帧不会清掉它 | 还没收到过好帧、或 rx 为 NULL：返回 0，并把 `*data` 置为 NULL。data 参数本身为 NULL 时只返回长度 |

## 例子

数据 `01 02 03` 的帧是：`AA 03 01 02 03 crcL crcH`，其中 CRC 计算的是 `03 01 02 03` 四个字节。
