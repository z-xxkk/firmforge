# Modbus RTU 从机 modbus_slave

实现 `include/modbus_slave.h` 中声明的全部函数：一个支持功能码 03（读保持寄存器）和 06（写单个寄存器）的 Modbus RTU 从机。

## 约束

- 不能使用动态内存、标准输入输出函数，不能用递归。
- 头文件由任务锁定，不能修改；可以把实现拆成多个 `.c` / `.h` 文件（例如 CRC、帧处理、功能码处理分开）。
- CRC 要自己实现。

## 用法

- `modbus_slave_init(s, address, regs, reg_count)`：本机地址 1–247；`regs` 是调用方提供的保持寄存器数组，寄存器地址从 0 开始编号。
- **调用方负责分帧**（RTU 用 3.5 字符静默时间分帧），每次把**一整帧**交给 `modbus_slave_handle(s, req, req_len, resp, resp_size)`。函数把响应帧写进 `resp`，返回响应长度；**返回 0 表示不回复**。

## 规范要点（摘自 Modbus 官方规范）

**RTU 帧**（《MODBUS over Serial Line V1.02》）：`从站地址 1 字节 | 功能码 1 字节 | 数据 | CRC 2 字节`
- CRC-16/MODBUS（初值 0xFFFF，反射多项式 0xA001），覆盖地址到数据的全部字节，**低字节在前**；
- 地址 0 是广播；1–247 是从站地址；248–255 保留；
- 广播请求**不回复**；广播必然是写命令；
- CRC 错误的帧、不是发给本机的帧：丢弃，不回复；
- RTU 帧最长 256 字节。

**功能码**（《MODBUS Application Protocol V1.1b3》）：

| 功能码 | 请求（地址和 CRC 之间） | 正常响应 |
|---|---|---|
| 03 读保持寄存器 | 起始地址 2 字节 + 数量 2 字节（高字节在前），数量 1–125 | 03 + 字节数（2 × 数量）+ 每个寄存器 2 字节（高字节在前） |
| 06 写单个寄存器 | 寄存器地址 2 字节 + 值 2 字节 | **原样回显请求** |

**异常响应**：`地址 | 功能码 + 0x80 | 异常码 | CRC`。异常码：01 不支持的功能码；02 地址非法；03 数据值非法（包括请求长度不对）；04 设备故障。

**检查顺序**（规范图 13、图 16）：先查功能码（01）→ 再查数量 / 数值（03）→ 再查地址（02）→ 执行出错（04）。

## 处理规则

| 情况 | 应该怎样 |
|---|---|
| 初始化：地址不在 1–247、regs 为 NULL、reg_count 为 0、s 为 NULL | 返回 false；之后 `modbus_slave_handle` 一律返回 0 |
| 帧长度小于 4 或大于 256 | 返回 0 |
| CRC 不对 | 返回 0 |
| 地址既不是本机也不是 0 | 返回 0 |
| 功能码不是 03 或 06 | 异常 01 |
| 03 或 06：帧总长度不是 8 字节 | 异常 03 |
| 03：数量不在 1–125 | 异常 03 |
| 03：起始地址 + 数量 > reg_count | 异常 02（例：100 个寄存器时，起始 96 数量 4 可以；起始 96 数量 5 不行） |
| 06：寄存器地址 ≥ reg_count | 异常 02 |
| 06：正常 | 写入寄存器，响应与请求帧完全相同 |
| 广播（地址 0）+ 06 且合法 | 写入，返回 0 |
| 广播 + 其他任何情况（03、不支持的功能码、出错） | 什么都不做，返回 0 |
| 正常响应放不下 resp_size | 若 resp_size ≥ 5，回复异常 04，**不执行**写入；否则返回 0 |
| 异常响应（5 字节）放不下 | 返回 0 |
| req 或 resp 为 NULL | 返回 0 |

## 例子

本机地址 0x11，寄存器 107–109（地址 0x6B–0x6D）的值是 0x022B、0x0000、0x0064：

- 请求 `11 03 00 6B 00 03 crcL crcH` → 响应 `11 03 06 02 2B 00 00 00 64 crcL crcH`
- 请求 `11 06 00 01 00 03 crcL crcH` → 寄存器 1 变为 3，响应与请求相同
