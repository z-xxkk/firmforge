# Flash 键值存储 flash_kv

实现 `include/flash_kv.h` 中声明的全部函数：在片内 NOR Flash 的两个扇区上保存"id → 数据"键值对，断电不丢，写到一半断电也能恢复。设计参照 Zephyr NVS 的核心原则（简化版）。

## 约束

- 不能使用动态内存、标准输入输出函数，不能用递归。
- 只能通过 `include/hal_flash.h` 里的三个函数访问 Flash，不能自己实现它们（由使用方提供；写单元测试时请在 `tests/` 里自己写一个模拟的 Flash，写入时只能把 1 变成 0）。
- 两个头文件都由任务锁定，不能修改。

## Flash 的特点

- 擦除后每个字节都是 FFh；写入只能把位从 1 变成 0，不能原地改写；要改回 1 只能擦除整个扇区。
- 共 2 个扇区，每个 1024 字节：扇区 0 是地址 0–1023，扇区 1 是 1024–2047。

## 存储格式

**扇区头**（扇区开头 4 字节）：`4Bh 56h`（字符 'K' 'V'）+ 2 字节序号（低字节在前）。头有效的扇区才是"在用"的扇区。

**条目**（从扇区偏移 4 开始，一条接一条）：

| 偏移 | 内容 |
|---|---|
| 0–1 | id（低字节在前），范围 0–FFFEh |
| 2–3 | 数据长度 len（低字节在前），0–64；**0 表示删除** |
| 4–5 | CRC（低字节在前） |
| 6… | len 字节数据 |
| 之后 | 补 FFh，使整条长度是 4 的倍数：条目大小 = (6 + len + 3) ÷ 4 × 4 |

**CRC**：CRC-16/CCITT-FALSE（多项式 1021h，初值 FFFFh，不反射，结果不异或），依次计算条目的前 4 个字节（id、长度）和 len 字节数据。核对用："123456789" 的结果是 29B1h。`kv_crc16(data, len, crc)` 从给定的 crc 继续算，这样可以分段计算。

**一条条目用一次 `hal_flash_write` 写完**（头和数据一起）。写到一半断电时，CRC 一定对不上。

## 读条目时怎么判断

从偏移 4 开始逐条读：
- 6 字节头全是 FFh：后面是空白，这里就是"下一条写入的位置"；
- id 为 FFFFh、长度大于 64、条目超出扇区、或 CRC 不对：**损坏**。损坏处及之后的空间都不再使用（"下一条写入的位置"记为扇区末尾，下一次写入会触发整理），之前的有效条目照常使用；
- 剩余空间放不下 6 字节头：到结尾。

同一个 id 有多条时，**最后一条**为准；最后一条长度为 0 表示已删除。

## 函数行为

**`kv_mount(kv)`**：读两个扇区的头，然后扫描在用的扇区，算出"下一条写入的位置"。

| 情况 | 应该怎样 |
|---|---|
| 两个扇区的头都无效（空白 Flash） | 擦除两个扇区，在扇区 0 写序号 0 的头 |
| 只有一个有效 | 用它（另一个可能是整理到一半的残留，不用管，下次整理时会先擦除） |
| 两个都有效（整理在最后一步断电） | 用序号"更新"的那个：(uint16_t)(s1 − s0) 在 1–7FFFh 之间说明扇区 1 更新，否则用扇区 0；擦除另一个 |

成功返回 `KV_OK`；kv 为 NULL 返回 `KV_ERR_PARAM`；Flash 出错返回 `KV_ERR_FLASH`。

**`kv_write(kv, id, data, len)`**
- kv 为 NULL、id 为 FFFFh、data 为 NULL、len 为 0 或大于 64：`KV_ERR_PARAM`；没挂载：`KV_ERR_NOT_MOUNTED`。
- 当前值（最新一条、未删除）和要写的完全相同：**什么都不写**，返回 `KV_OK`。
- 在用扇区剩余空间放得下：追加一条，返回 `KV_OK`。
- 放不下：**整理**（见下），新值随整理一起写入。
- `hal_flash_write` 失败：返回 `KV_ERR_FLASH`；这次写的位置及之后的空间不再使用。

**整理**（扇区写满时）：
1. 擦除另一个扇区；
2. 按条目在在用扇区里的先后顺序，把每个 id 的**最新一条**复制过去（已删除的 id、正在写的这个 id 跳过）；
3. 写入新的条目（删除操作触发的整理不写，这个 id 直接不复制）；
4. 在新扇区写扇区头，序号 = 旧序号 + 1（**最后才写头**，之前任何一步断电，旧扇区都还完整有效）；
5. 擦除旧扇区，新扇区成为在用扇区。

第 2、3 步之后放不下：返回 `KV_ERR_NO_SPACE`，不写头，在用扇区和其中的数据保持不变。

**`kv_read(kv, id, buf, cap, len)`**
- kv 或 len 为 NULL、buf 为 NULL 而 cap 大于 0、id 为 FFFFh：`KV_ERR_PARAM`；没挂载：`KV_ERR_NOT_MOUNTED`。
- 没有这个 id 或已删除：`KV_ERR_NOT_FOUND`。
- `*len` = 数据长度；cap 小于长度：`KV_ERR_BUF_TOO_SMALL`（不写 buf）；否则把数据复制到 buf，返回 `KV_OK`。

**`kv_delete(kv, id)`**
- 参数和挂载检查同 `kv_write`（不需要 data）。
- 没有这个 id 或已经删除：什么都不写，返回 `KV_OK`。
- 否则追加一条长度为 0 的条目；放不下时整理（这个 id 不复制，也不写删除条目）。

**`kv_free_space(kv)`**：在用扇区里还能写多少字节（1024 − 下一条写入的位置）；kv 为 NULL 或没挂载返回 0。

## 例子

空白 Flash 挂载后：扇区 0 前 4 字节为 `4B 56 00 00`，剩余空间 1020。

`kv_write(kv, 1, {0x11, 0x22}, 2)` 写入的条目（8 字节）：

```
01 00  02 00  CRC低 CRC高  11 22
```

CRC = CRC-16/CCITT-FALSE(01 00 02 00 11 22)。之后剩余空间 1012。
